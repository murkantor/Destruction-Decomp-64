# DD64

A matching decompilation of Destruction Derby 64 (USA). The build turns C and assembly back into a ROM that is byte for byte identical to the original.

Status: the ROM builds and matches. 1510 of 1548 functions (99% of the code by size) are in C. Three heap functions (`Heap_Alloc`, `Heap_AllocAlt`, `Heap_Free`) are still assembly included from `src/heap.c`; the other 38 are hand-written assembly that was assembly in the original too (libultra CPU, cache, TLB and thread routines, libgcc 64-bit helpers, `bcopy`/`bzero`/`bcmp`). `make progress` prints the current numbers. Files outside `src/auto/` are cleaned up, with real names and types; `src/auto/` holds C generated with m2c that still uses placeholder types.

You need your own copy of the ROM. It is not included and must never be committed.

## Requirements

- Linux (or WSL) with `make`, `curl`, `sha1sum` and Python 3.
- MIPS binutils: `mips-linux-gnu-as`, `ld`, `objcopy`, `objdump`.
- KMC GCC 2.7.2 and its assembler, which the game was built with. `tools/setup.sh` downloads them.

On Debian or Ubuntu:

```sh
sudo apt install make curl python3-venv binutils-mips-linux-gnu
```

## Build

1. Copy your ROM to `baserom.z64` in the repo root.
2. Set up Python and the compiler:
   ```sh
   python3 -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   tools/setup.sh
   ```
3. Split the ROM into assembly and data:
   ```sh
   make extract
   ```
4. Build and check the result:
   ```sh
   make
   ```
   A matching build prints `build/dd64.z64: OK`.

Run `make extract` again after changing `dd64.yaml` or `symbol_addrs.txt`. `make progress` shows how much is in C. `make distclean` removes everything generated.

## Layout

| Path | Contents |
|---|---|
| `dd64.yaml` | splat config: where each segment of the ROM starts |
| `symbol_addrs.txt` | Names for functions and data, fed to splat |
| `linker_syms.txt` | Symbols defined at link time, such as segment ROM addresses |
| `src/` | Decompiled C: `boot.c`, `romfile.c` (ROM file layer for the zip), `pool.c` (fixed-size block pools), `mem.c` (main heap allocations) |
| `src/libultra/` | Nintendo SDK and audio library functions, one file each, named after the function |
| `src/auto/` | C generated by m2c that matches but uses placeholder types (`include/m2c.h`) |
| `include/` | Headers. `hardware_syms.ld` holds hardware register and libultra low-memory addresses |
| `include/ids.h` | Sound, sprite and text IDs, generated from the prototype |
| `include/car.h` | Car and AI fields known so far |
| `tools/` | Compiler setup and the `move` fix for the assembler |
| `tools/proto/` | Scripts that compare the prototype with retail |
| `tools/autodecomp.py`, `tools/apply_auto.py` | Generate matching C with m2c and add it to the build |
| `tools/permute_setup.py`, `tools/permute_collect.py` | Run decomp-permuter on near misses and collect the matches |
| `tools/rename.py` | Apply names from `symbol_addrs.txt` to the C |
| `tools/gen_docs.py` | Write the function and file lists in `docs/` |
| `tools/build_nonmatching.sh` | Build a test ROM with the drafts listed in `nonmatching/test_build.txt` linked in place of their asm (`build/dd64_nonmatching.z64`) |
| `tools/n64crc.py` | Recompute or check the boot checksum of a ROM (CIC-6102) |
| `tools/diff_func.py` | Show a hand-written function's code next to the original |
| `tools/check_c.py` | Check hand-written functions against the ROM before `apply_auto.py` adds them |
| `diff_settings.py` | Config for [asm-differ](https://github.com/simonlindholm/asm-differ) |
| `asm/`, `assets/`, `build/` | Generated, not committed |

## Decompiling a function

1. Find the function in `asm/`. To work on it in C, give the file a `c` subsegment in `dd64.yaml`, run `make extract`, and splat writes a C file with an `INCLUDE_ASM` line per function.
2. Replace one `INCLUDE_ASM` line with C.
3. Compare against the original with asm-differ:
   ```sh
   python3 path/to/asm-differ/diff.py -m boot
   ```
4. `make` must still print `OK` before you commit.

## Naming symbols

1. Add `name = 0xADDRESS; // type:func` (or without the type for data) to `symbol_addrs.txt`.
2. Update the C and rebuild:
   ```sh
   python3 tools/rename.py
   make extract
   make
   ```

The libultra, libc and audio library names came from [n64sym](https://github.com/shygoo/n64sym). Its hits inside the game code were false positives and were left out.

## Generating C with m2c

[m2c](https://github.com/matt-kempster/m2c) gets many small functions right first time. These scripts keep only output that compiles to exactly the original code.

1. Get m2c:
   ```sh
   git clone https://github.com/matt-kempster/m2c tools/m2c
   pip install pycparser
   ```
2. Try every function still in `asm/` and keep the matches in `build/auto/`:
   ```sh
   python3 tools/autodecomp.py tools/m2c
   ```
3. Write them to `src/auto/` and add them to `dd64.yaml`, then rebuild:
   ```sh
   python3 tools/apply_auto.py
   make extract
   make
   ```

Functions that come close are saved in `build/auto/near/`, named by how many instructions differ. [decomp-permuter](https://github.com/simonlindholm/decomp-permuter) can often finish them:

```sh
git clone https://github.com/simonlindholm/decomp-permuter tools/permuter
python3 tools/permute_setup.py
python3 tools/permuter/permuter.py build/permute/func_80012345 --stop-on-zero
python3 tools/permute_collect.py
python3 tools/apply_auto.py build/permuted
make extract
make
```

When you clean up a file in `src/auto/`, give it real types and names and move it out of `auto/` (rename its subsegment in `dd64.yaml` to match).

## Compiler

| Setting | Value |
|---|---|
| Compiler | KMC GCC 2.7.2 |
| Flags | `-O2 -G0 -mips3 -mgp32 -mfp32` |
| Assembler | KMC's binutils 2.6 for files that are all C, like the original build. `tools/elf_trim.py` cuts the padding it adds after `.text` and fixes its symbol table for modern ld. Files with `INCLUDE_ASM` use modern GNU as, with `tools/fix_move.sed` to encode `move` the KMC way |
| libultra | 2.0I, built 31 Jul 1998, with asserts |
